# Chrono Lenta — Система управления эфирным временем и квотами In-Store видеорекламы

**Chrono Lenta (Ad Scheduler)** — корпоративное B2B веб-приложение для планирования рекламных кампаний (РК), ведения очереди бронирования эфира и автоматического контроля лимитов хронометража на видеоэкранах розничной сети (**179 торговых комплексов**: **95 гипермаркетов (ГМ)** и **84 супермаркета (СМ)** в **12 городах**).

---

## Бизнес-задача и ценность продукта

Штатное программное обеспечение для трансляции видеороликов в торговых залах не имеет встроенного календаря планирования сетки вещания, контроля пересечений по датам и инструмента предварительного бронирования квот. Ручное ведение расписания в таблицах приводило к риску перегруза эфира и конфликтам приоритетов при распределении рекламных слотов.

**Что решает система:**

* **Единый источник данных в реальном времени:** отображает точную эфирную загрузку каждого из 179 ТК на любую выбранную дату в прошлом, настоящем или будущем.


* **Автоматическая защита квот эфира:** математическое ядро в реальном времени контролирует лимиты (**180 сек** суммарно / **125 сек** платный блок / **55 сек** бесплатный блок) и предупреждает о перегрузе до публикации ролика.


* **Прозрачная очередь бронирования (FIFO):** фиксирует заявки сотрудников по точному времени внесения и автоматически рассчитывает доступность квот с учётом приоритета в очереди.

## Ключевые возможности системы

### 1. Дашборд для коллег («Экраны ТК»)



* **Три изолированных режима просмотра с визуальной индикацией активного экрана:**
* **Список ТК:** сводная таблица по всем 179 торговым комплексам с расчётом суммарного, платного (включая свободный остаток в секундах) и бесплатного хронометража, а также сворачиваемыми карточками активных и запланированных РК.


* **Матрица (`Кампании × ТК`):** двумерная сетка пересечений всех рекламных кампаний и торговых комплексов с закреплёнными заголовками и строкой итогов по лимитам.


* **Очередь бронирования («Брони»):** реестр предварительных броней коллег с автоматической проверкой попадания каждой заявки в квоту ТК.




* **Индикатор высвобождения эфира («Освободится»):** автоматически вычисляет ближайшую дату окончания роликов в каждом ТК и количество освобождаемых секунд (например, `-10с с 03.11` или `-15с с 01.11`).


* **Режим симуляции «Учитывать бронь в ТК»:** позволяет в один клик наложить все заявки из очереди бронирования поверх текущего эфира для оценки прогнозируемой загрузки каждого ТК.


* **Гибкая система фильтров:** фильтрация по формату магазина (`Все` / `ГМ` / `СМ`), городу, дате проверки, типу оплаты (`платный` / `не платный`), формату РК (`ГМ`, `СМ`, `ГМ+СМ`, `част.ГМ`, `част.СМ`), заказчику и наличию превышений квот.



### 2. Интеллектуальное бронирование эфирного времени



* **Предварительный расчёт конфликтов:** прямо в момент заполнения диалогового окна бронирования система симулирует нагрузку на каждый день выбранного периода и выводит список ТК, где возникнет оранжевое или красное предупреждение.
* **Валидация номеров ТК:** автоматическое распознавание номеров ТК из текстовой строки, отсев несуществующих комплексов и удаление ошибочных номеров одной кнопкой.
* **Гибкий выбор торговых комплексов:** выбор формата РК не перезаписывает введённый вручную список ТК; для быстрого набора доступны кнопки `Все ГМ (95)`, `Все СМ (84)`, `ГМ+СМ (179)`, `Очистить`, а также интерактивный подбор по городам и адресам.



### 3. Панель администратора («Админ: управление рекламными кампаниями»)



* **Защита доступа:** вход в административный раздел защищён ПИН-кодом с функцией смены ПИН-кода и кнопкой выхода.


* **Аналитика за период:** автоматический подсчёт опубликованных кампаний за выбранный диапазон дат (`Всего роликов (РК)`, `Для ГМ`, `Для СМ`) и быстрый фильтр «Текущий месяц».


* **Публикация брони в 1 клик:** кнопка **«В эфир»** в блоке очереди бронирования автоматически переносит все параметры заявки коллеги в форму создания рекламной кампании.


* **Мониторинг истекающих размещений:** фильтр **«Истекают ≤ 3 дн.»** и специальные бейджи в таблице выделяют активные кампании, у которых заканчивается срок показа.


* **Безопасное управление реестром и Корзина (30 дней):**
* Редактирование и дублирование кампаний (**«Копировать»**) с сохранением всех настроек и списка ТК.


* Умное выделение строк строго в рамках текущего отфильтрованного списка с отдельным счётчиком выбранных завершённых кампаний.
* Выделенная кнопка **«Удалить все завершённые»** для быстрой очистки реестра без риска затронуть активные или запланированные кампании.
* **Корзина с хранением 30 дней и кнопкой Undo:** удалённые кампании сохраняются в корзине на 30 дней с возможностью мгновенной отмены последнего удаления (**«Отменить удаление»**) или выборочного восстановления со всеми привязанными ТК.


* **Экспорт в Excel (CSV):** выгрузка в один клик как таблицы загрузки экранов ТК, так и отфильтрованного реестра рекламных кампаний (`UTF-8 BOM`).

## Математическая модель квот и индикация рисков

Для каждого торгового комплекса действуют строгие нормативы эфирного блока:

| Параметр | Лимит | Описание |
| --- | --- | --- |
| **Суммарный хронометраж** | **≤ 180 сек**

 | Максимальная общая длительность всех роликов в эфире одного ТК.

 |
| **Платный хронометраж** | **≤ 125 сек**

 | Приоритетная коммерческая квота (70% эфирного времени).

 |
| **Бесплатный хронометраж** | **≤ 55 сек (база)**

 | Промо-квота (30% эфирного времени). Допускается использование свыше 55с при условии соблюдения общего лимита 180с и сохранения резерва в платном блоке > 20с.

 |

### Уровни предупреждений

* 🟢 **В норме (`OK`):** суммарный хронометраж ≤ 180с, платный ≤ 125с, свободный остаток платного времени при наличии бесплатных роликов > 20 секунд.


* 🟠 **Оранжевое предупреждение (`Orange`):** в ТК стоят бесплатные ролики, а свободный резерв для коммерческой рекламы сократился до **10–20 секунд**.
* 🔴 **Критический перегруз (`Red`):** превышен общий лимит (> 180с), превышен платный лимит (> 125с) или при наличии бесплатных роликов остаток под платную рекламу составляет **0–5 секунд**.

## Интерфейс и UX-архитектура

* **Фиксированные панели управления (`Locked Top Bars`):** шапка навигации, панели фильтров, сводная аналитика и очередь бронирования закреплены в верхней части экрана; вертикальная и горизонтальная прокрутка работает исключительно внутри табличного окна с данными.
* **Единый дизайн-код Apple Liquid Glass:** полупрозрачные панели с размытием фона (`backdrop-filter: blur(28px)`), компактная однострочная вёрстка высокой плотности и унифицированные контрастные модальные окна загрузки данных и бронирования.


* **Визуальная навигация:** активные разделы («Экраны ТК (Для коллег)» / «Админ (Загрузка данных)») и режимы просмотра («Список ТК» / «Матрица» / «Брони») выделены акцентными капсульными кнопками.


* **Переключатель «День / Ночь»:** мгновенная смена светлой и тёмной темы оформления с сохранением пользовательского выбора в `localStorage`.

## Локальный запуск и сборка

### 1. Системные требования

* **Node.js** ≥ 20.x
* **pnpm** ≥ 10.x
* **PostgreSQL** (локальный инстанс или облачная БД)

### 2. Установка зависимостей

```bash
pnpm install

```

### 3. Переменные окружения

Создайте файл `.env` и укажите строку подключения к базе данных:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/chrono_lenta"
PORT=3000

```

### 4. Сборка и старт

```bash
# Сборка клиентского приложения
pnpm --filter @workspace/ad-scheduler run build

# Сборка API-сервера
pnpm --filter @workspace/api-server run build

# Запуск production-сервера
node artifacts/api-server/dist/index.cjs

```
